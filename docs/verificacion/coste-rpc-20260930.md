# Separación de ejecución SQL y latencia HTTP

El [registro del 30 de septiembre](datos-coste-rpc-20260930.json) compara contadores acumulados de `pg_stat_statements` con la lectura anterior de las 23:38 UTC. No se restablecieron estadísticas ni se registraron textos de consultas, cookies o credenciales. PostgreSQL expresa estos tiempos de ejecución en milisegundos; se distinguen de los campos brutos de los registros HTTP. [Referencia de PostgreSQL](https://www.postgresql.org/docs/17/pgstatstatements.html).

Entre ambas lecturas, `aulify_sync` pasó de 54.969 a 64.330 llamadas: 9.361, coincidentes con el sondeo. El tiempo de ejecución acumulado aumentó aproximadamente 12.043,94 ms, una media de **1,29 ms por llamada**. La coincidencia no vincula cada consulta a una solicitud individual ni convierte esa media en un percentil. El p95 HTTP medido de 2.404,40 ms incluye otras esperas; los datos no permiten atribuirlas a red, pool o un componente concreto.

En el mismo intervalo más amplio hubo 713 proyecciones de actividad y 407 comandos, incluyendo preparación y otras verificaciones. Sus medias incrementales son aproximadamente 108,19 y 24,58 ms, respectivamente. No representan exclusivamente los comandos de la ráfaga.

Se inspeccionó además la proyección de un alumno ficticio en una actividad vigente con cincuenta intentos sin vencer. Un primer `EXPLAIN ANALYZE` midió 322,19 ms; dos lecturas posteriores en la misma sentencia midieron 55,35 y 21,66 ms, con 15.036 bytes cada una. Esta variación desaconseja presentar una llamada aislada como capacidad del servicio. La inspección encontró construcción duplicada de las preguntas dentro de `student_activity`; su eliminación requiere comparación de contenido y permisos antes de incorporarse.

El intento de habilitar estadísticas de consultas anidadas fue rechazado por permisos. No se alteró la configuración ni se insistió con otro privilegio.

El ejecutor del siguiente sondeo conserva inicio y fin de cada solicitud usando el reloj monotónico anclado de Node. Así podrá relacionar las esperas con fases de la prueba; no se reconstruyen tiempos individuales de informes anteriores que no los registraban. Se verificó la sintaxis del cambio sin iniciar otra carga. Q-06 y Q-09 permanecen pendientes.
